# QuantDeus — внедрение WordPress-native автоворонок (только staging)

Дата обследования: **2026-10-30**. Связанные задачи: #644, draft PR #645, QA gate #633.

## Проверенные факты (read-only, production не изменён)

- Основной сайт: https://quantdeus.ru — WordPress **7.1.4**, PHP **8.3.36**, MariaDB **10.11.19**, среда `production`.
- Получен список **5 плагинов**: 3 активны; `Groundhogg` и `FluentSMTP` **не установлены**. Из существующих активны QuantDeus YooMoney, Telegram Login, miniOrange MCP.
- Получен список **26 опубликованных страниц**. Подтверждены адреса: `/news/`, `/manifesto/`, `/research/`, `/books/`, `/knowledge/`, `/ai-fleet/`, `/services/business-automation/`, `/media/`, `/community/`.
- WordPress Cron: 14 запланированных событий, **0 просроченных на момент проверки**. Это **не доказывает** пригодность текущего расписания для массовых писем.
- **Privacy Policy — страница #3** назначена политикой конфиденциальности, но находится в статусе **draft**; для посетителей она недоступна. Требуется отредактировать корректные сведения об обработке данных и опубликовать до приёма email-адресов.
- WordPress MCP позволяет читать и управлять **уже установленными** плагинами, но **установку новых плагинов этим подключением выполнить нельзя**. Поэтому установка в рабочий WordPress **не производилась**.

- **Создан непосредственно в WordPress черновик страницы подписки #218**: slug `newsletter`, статус `draft`, редактирование: https://quantdeus.ru/wp-admin/post.php?post=218&action=edit. Страница содержит 4 темы, пояснение double opt-in и пустой слот для формы; **формы/сбора данных пока нет**.

## Решение по компонентам

| Компонент | Ответственность | Действующий статус |
|---|---|---|
| Groundhogg (WordPress) | Согласие, сегменты, формы, очередь, отписка, частота | Не установлен; только staging-план |
| FluentSMTP (WordPress) | Перехват `wp_mail`, интеграция SMTP/API, тестовая отправка | Не установлен, провайдер не настроен |
| SMTP/ESP | Фактическая доставка почты и лимиты | **Не выбран / не оплачен** |
| GitHub Actions | Проверка конфига, тесты движка, синтетический dry-run | Реализован в draft PR #645 |
| Private subscriber store | Закрытые записи подписчиков и отказов от писем | Не настроен; не хранить контакты в GitHub |

У Groundhogg в справке описано, что неподтверждённый контакт **может** оказаться marketable по настройкам по умолчанию. Поэтому нельзя считать двойное согласие реализованным только после установки. Состояния и настройки нужно проверить **в интерфейсе staging**.

## Действия в панели WordPress после готовности staging

- Официальная установка: **Плагины → Добавить новый → Groundhogg (groundhogg) → Установить**; затем **FluentSMTP (fluent-smtp)**. Не заменять плагины с похожими именами сторонними ZIP.
- После установки Groundhogg: **Groundhogg → Funnels → Create New → Web Form benchmark**, получить точный shortcode вида `[gh_form id="реальный-ID"]` из вкладки Embed. **Не придумывать ID**. Заменить только специальный слот в черновике WP #218 посредством вставки блока «Шорткод» после успешных тестов. Пока форма не готова, страница остаётся черновиком.
- Privacy Policy #3: проверка содержимого, публикация корректной политики и установка публичного URL **до** публикации подписной формы. Не считать встроенный шаблон WP юридически готовым.
- Конфигурация Groundhogg: **Only send to confirmed emails = ON**, **grace period = 0**, **Enable GDPR features = ON**, **Do not send email without consent = ON**, **One-click unsubscribe = ON**. Проверить на staging поведение неподтверждённых адресов и double opt-in.
- Email confirmation: в транзакционном письме после формы использовать документированный Groundhogg replacement code `{confirmation_link}`; маркетинговые сообщения только после шага «Opt-in Status Confirmed».
- FluentSMTP: **Settings → FluentSMTP**; без подключённого сервиса не считать письмо доставляемым; выбрать и верифицировать SMTP/API провайдера, затем тестировать лишь согласованные тестовые ящики. Транспорт `wp_mail` не считать доказанным для Groundhogg без проверки фактического лога.

Документы: https://help.groundhogg.io/article/42-ghform , https://help.groundhogg.io/article/381-how-to-confirm-an-email-address , https://help.groundhogg.io/article/719-settings , https://fluentsmtp.com/docs/installing-fluent-smtp/ .

## Безопасный маршрут до работающего пилота

1. Создать **отдельный staging/бэкап с откатом** и проверить, что тестовые данные не уходят в production (не копировать реальных подписчиков).
2. Только на staging установить **Groundhogg** и **FluentSMTP** из проверенных источников через WP admin/хостинг; проверка совместимости и smoke-test с текущими плагинами. Для действующего сайта установка требует **отдельного разрешения**.
3. Groundhogg: включить «Only send to confirmed emails»; **grace period = 0**; включить **GDPR features** + **Do not send email without consent**; выключить предварительно отмеченное согласие. Проверить вариант реализации настоящего double opt-in и отдельное хранение метки согласия.
4. Форму сделать **непубличной** до end-to-end проверки: email, четыре темы, явное согласие без галочки по умолчанию, link на фактически опубликованную privacy policy, ожидаемая частота ≤1 маркетингового письма за 7 суток.
5. До проверки общего ограничения по частоте подписчик должен иметь **не более одного активного маркетингового сегмента**. Один общий лимит для нескольких тем нельзя считать реализованным автоматически Groundhogg. Проверить поведение на mock/test mailboxes.
6. Настроить единственную очередь **Groundhogg** и надежный серверный cron WordPress (рекомендации Groundhogg для `wp-cron.php` и `gh-cron.php`); отдельное расписание GitHub Actions **не должно** вызывать отправку или запускать дубль очереди.
7. Настроить FluentSMTP только после выбора сервиса/отправителя и проверки SPF/DKIM/DMARC и доступных квот. Отправка на собственные специально выделенные тестовые ящики — только после явного разрешения на staging-тест, никаких маркетинговых рассылок. Четыре сегмента и 10 русскоязычных черновиков лежат в `newsletter-message-drafts.json`.
8. Провести E2E на тестовых записях: unconfirmed, unsubscribed, bounce, complaint, отсутствие согласия, повтор webhook, повтор cron, изменение темы, отписка в 1 клик, реальный sender и delivered. Триггеры отправки и журнал отказов/ретраев в **закрытом** хранилище, не в Actions artifacts.
9. Получить зелёные **два QA валидатора**, ревью Tuvok/Data и согласие владельца **отдельно** на публикацию формы и **отдельно** на запуск реальных писем. Issue #633 не обходить.

## Что сознательно НЕ сделано

На production подготовлена **одна непубличная страница-черновик #218**. Нет установки плагинов на `quantdeus.ru`, публичной формы, реальных абонентов, писем, SMTP ключей, расходов, подтверждённого E2E, импорта контактов или изменений DNS. Код в этом PR — черновики, сухая проверка и план внедрения.

## Следующий минимальный обратимый шаг

Создать изолированную staging-копию (без базы реальных подписчиков) и установить Groundhogg + FluentSMTP **там**, включив только закрытые тестовые сценарии. До этого можно ревьюить и тестировать JSON/движок в GitHub.
