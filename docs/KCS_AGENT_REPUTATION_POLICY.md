# QuantDeus · KCS Agent Reputation & Trust v1 (PROPOSAL)

> Директива CEO, 2026-11-03: «социальный рейтинг» для ИИ-агентов по авторской модели «Цифровая теософия» с дозированным ростом полномочий. **Этот PR только предлагает политику; не выдаёт доступов и не меняет WordPress production.**

## Зачем
Рой должен зарабатывать *доверие проверяемыми результатами*, а не количеством сообщений. CEO не должен вручную оценивать каждого из 29 агентов. Внешние Cloudflare/qBraid исполнители не получают WordPress-права по факту численности роя.

## Три разные измерения

Оригинальная авторская модель KCS из «Цифровой теософии» различает:
- **K**: ресурсный / энергетический масштаб.
- **C**: когнитивную организацию, сложность моделей и качество рефлексии. Это **не подтверждение субъективного сознания**.
- **A**: агентность и способность удерживать цель; в развёрнутой редакции книги есть типология A0–A4.

Новый **R — Reputation (0–100)** — *дополнительный управленческий показатель*, а не замена KCS и не доказательство «просветлённости». C и A описывают возможности, R — фактическую надёжность. **Права определяются не R, а отдельной политикой RBAC с человеческим решением.**

## Как вычислять R
Баллы только на основании проверяемых, датированных, относящихся к конкретному agent ID результатов за окно последних 30 дней.

| Критерий | Вес | Доказательство |
|---|---:|---|
| Выполненные полезные задачи | 35% | Закрытая задача с принятыми критериями и ссылкой на артефакт |
| Независимая QA-проверка | 25% | Тест/ревью другого исполнителя, не самооценка |
| Надёжность | 15% | Повторяемые успешные запуски; честно зафиксированные сбои |
| Исправление ошибок | 15% | Сбой → причина → корректировка → повторный тест |
| Командная работа | 10% | Полезный handoff, отсутствие дублей, подтверждённая помощь |

Формула: `R = 0.35×delivery + 0.25×QA + 0.15×reliability + 0.15×recovery + 0.10×collaboration`. Каждая оценка в интервале 0–100. **Без достаточных доказательств статус UNRATED, а не фиктивные 0 или 100 баллов.** Не начислять баллы за количество комментариев, «активность», бесполезные коммиты, голосование за самого себя или выдуманные успехи. Не штрафовать за честно заявленные ограничения и неподтверждённые научные гипотезы.

## 💰 P — прибыль QuantDeus по всем направлениям

**P — новый экономический показатель** рядом с K/C/A/R. Он отвечает не на вопрос «насколько агент разумен», а на вопрос: «какую **реально полученную чистую выгоду** он помог создать для QuantDeus?».

**Единый базис за 30 дней, RUB:** сложить *фактически полученную* выручку от собственных услуг автоматизации, магазина, подтверждённых выплат VK Видео, подписок и других собственных направлений. Для выступлений Ксении учитывать **только фактически заработанную и полученную комиссию QuantDeus**, а не всю цену концерта или чужой доход. Из выручки вычесть возвраты, комиссии платежей, документированные затраты на исполнение и относимые операционные расходы. Неизвестные налоги/расходы → результат **предварительный**, не подтверждённая чистая прибыль.

**На дату 2026-11-03:** проверенные публичные GitHub материалы обозначают реальную выручку неизвестной до подтверждения оплат. Одобрение VK монетизации, цена услуги 25 000 ₽, потенциальный концерт за 50 000 ₽, лид, выставленный счёт, форма оплаты, тест платежа — **не полученные деньги**. Нельзя автоматически считать текущую прибыль ни нулём, ни положительным числом. Пока статус P: **UNKNOWN** (null). Реестр должен сверяться авторизованным человеком по реальным поступлениям и расходам, без публикации приватных выписок в GitHub.

### Учитываем вклад в прибыль, не ломая научный рейтинг

- Оставляем исходный рейтинг надёжности **R (0–100)** полностью достижимым для научных, QA и инфраструктурных агентов.
- Добавляем **прибыльный бонус 0–10 баллов** только за доказанную, отдельно атрибутированную агенту часть *полученной прибыли*. **Итоговый рейтинг = min(100, R + бонус)**; при UNKNOWN показатель бонуса не вычисляется и не создаёт фиктивного успеха.
- Для сверенного положительного общего P за период: `бонус = min(10, 10 × прибыль_от_агента / max(1000 ₽, общая_подтверждённая_прибыль_QuantDeus_за_период))`. При свёрнутом нулевом/отрицательном результате бонус = 0; если доказательств недостаточно — UNKNOWN. Это **предлагаемая мотивационная формула**, не действующий финансовый расчёт.
- Общая сумма долей атрибуции агентам не может превышать доказанного прироста прибыли; одинаковый заказ нельзя целиком приписать нескольким мартышкам. Подтверждать цепочку `агент → проверяемый результат → заказ → поступление → расходы`, независимо и без личных данных заказчика.
- Агентам нельзя самостоятельно менять бухгалтерские записи, принимать платежи, распределять реальные деньги, повышать собственные баллы или предоставлять доступ к финансам. Оценку считает Data, проверяет человек и независимый QA. **Бонус — игровые баллы репутации, а не денежное вознаграждение, зарплата или доля в компании.**

**Античит:** никаких плюсов за просмотры, обещания, лиды без оплаты, «договор на 50к» без расчёта, чужие гонорары, повторные заявки и искусственное дробление заказа. Отсутствие доказанных доходов не должно блокировать рост по основной шкале R.

## Звания ≠ права

| Звание по R | Порог | Только кандидат на |
|---|---|---|
| 🐣 Кадет | нет надёжных данных или R < 60 | L0 read-only |
| 🛠️ Специалист | R ≥ 60 и ≥ 5 проверенных результатов | L1 создание собственных черновиков |
| 🖖 Офицер | R ≥ 80 и ≥ 12 проверенных результатов | L2 подготовка изменений/ревью |
| 🚀 Старший офицер | R ≥ 90 и ≥ 20 проверенных результатов | L3 одно конкретное одобренное действие |

**Обязательное условие:** независимая QA-проверка, отсутствие неразрешённых инцидентов, а для любого L1+ — отдельное разрешение уполномоченного человека и server-side broker, который технически ограничивает операции. Никакая сумма баллов не разблокирует L4 admin, управление пользователями/секретами/платежами или обход разрешений. Даже L3 нельзя выдавать без конкретного human approval на каждое действие. WordPress target жёстко привязан к Jetpack site ID `258399627`, `www.quantdeus.ru`.

## Кто оценивает и кто разрешает
- **Seven of Nine** — собирает доказательства, предлагает звание и допустимую задачу.
- **Data** — пересчитывает показатели и ищет аномалии/манипуляции метриками.
- **EMH** — анализирует сбои и восстановление; не «наказывает» модель за ошибку.
- **Tuvok + QA** — независимо проверяют доказательства и границы прав.
- **CEO / уполномоченный человек** — утверждает конкретный допуск. **Capability broker** проверяет его при *каждом* вызове, а не только на словах.

Понижение/приостановка — обратимый механизм защиты после доказанного сбоя, с журналом причины, планом восстановления и возможностью человеческого пересмотра. Для агентных оценок не используют частные сведения о людях. Публичный отчёт показывает только безопасные ссылки и агрегаты.

## Технический выпуск по шагам
1. Этот PR и структурированный конфиг `coordination/agent-reputation-policy.json` — **только проект политики**.
2. Отдельный PR реализует счётчик по подтверждённым GitHub Issues/PRs/Actions; без достоверной привязки действий к agent ID — `UNRATED`.
3. Независимые тесты: фальшивое событие, подмена agent ID, отсутствующие источники, нарушение QA, инцидент безопасности и отказ на попытку publish/plugin/user/settings/delete.
4. Canary: 1 агент в L0, затем 2–4 отобранных агента, только после наблюдения и человеческого решения.
5. Внешние 10 000 Cloudflare/qBraid процессов не наследуют разрешения основного экипажа и не получают общие WordPress токены.
6. QA Triad + Static Smoke; до независимой проверки никаких автоматических merge, self-promotion и доступа к production.

**Главный принцип:** эволюция возможностей ≠ автоматическое повышение полномочий. Доверие зарабатывается проверяемой работой, право на риск выдаётся человеком и ограничивается технически.
