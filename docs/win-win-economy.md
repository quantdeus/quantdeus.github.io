# QuantDeus — экономика Win-Win / Triple-Win (рабочий контракт)

**Статус:** предложение к утверждению владельцем и QA.  
**Конституционная основа:** Манифест Неонового горизонта v4.0 (01.10.2026, Dropbox /quantdeus/QuantDeus_Manifest_Neon_Horizon_v4.0.pdf).  
**Исполняемая запись:** `coordination/civilization-doctrine.json#win_win_economy`.  
**Связанные направления:** Федерация независимых узлов, Future Fund, QuantDeus Store, Metaverse / Academy Credits.

## 1. Не путать маркетинг с экономическим результатом

`Win-Win` — взаимная добровольная польза. Для коммерческого проекта `Triple-Win` означает одновременно:
1. **Пользователь:** понятный полезный результат, информированное согласие, проверяемое качество, честные условия возврата или отказа.
2. **Автор / партнёр:** прозрачная оплата и права на результат, положительная ценность сотрудничества, возможность EXIT.
3. **QuantDeus:** устойчивость после прямых расходов, возврат инвестиций в инструменты и развитие, отсутствие скрытого субсидирования неоговорённой работы.

В отдельном общественно-экологическом измерении учитываются последствия для людей и среды, а не только денежный оборот. Для заявления о **строго положительном экологическом Triple-Win** нужны *измеренные* изменения `ΔU > 0` (польза), `Δπ > 0` (экономический итог) и `ΔH < 0` (вред снизился). Если измерений нет — `UNKNOWN`, а не `PASS`. Эти обозначения не означают, что такие результаты уже достигнуты.

## 2. Карточка проверки агентом (для каждого коммерческого решения)

| Поле | Что внести |
|---|---|
| Продукт / услуга | Название, ответственный, ссылка на действительную задачу/заказ |
| Добровольные стороны | Покупатель, исполнитель/автор, QuantDeus; кто несёт риск |
| Польза | Измеримый результат для покупателя; ссылка на приёмку, не просто обещание |
| Цена и расходы | Согласованная стоимость, комиссия платежей, труд/инфраструктура/налоги (неизвестные = UNKNOWN) |
| Выгода партнёра | Чистая выплата и согласованные права на IP/данные |
| Выгода платформы | Фактическая выручка **минус** известные прямые затраты, а не просмотры |
| Внешние эффекты | Ресурсы, энергия, приватность, экология и общественный вред |
| QA и согласие | Проверки, доказательства, условия EXIT/возврата, Human Override |
| Итог | PASS / FAIL / UNKNOWN / NOT_APPLICABLE с пояснением и ссылками |

`PASS` только при проверенных применимых условиях. `FAIL` при нарушении существенных прав, скрытых платежах, неподтверждённых гарантиях результата или очевидном ущербе. `UNKNOWN` при отсутствии данных; задача не может называться проверенной коммерческой победой.

## 3. Три практических примера — без выдуманной выручки

- **QuantDeus Store / услуги:** пользователь оплачивает только после подтверждения конкретного результата/условий; партнёр получает заранее согласованную долю; платформа показывает фактическую маржу. Заявки и оплаты учитываются отдельно от просмотров/уникальных посещений.
- **Метавселенная:** Academy Credits на этапе демо — внутренние условные баллы, **не** реальные деньги, инвестиции или NFT. Участник получает образовательную пользу, автор может предлагать оригинальные произведения в будущем только после QA и отдельного разрешения, платформа ведёт честный учёт затрат.
- **Научный проект / FTL / NX-01:** прибыльность не обязательна на этапе исследования. Подотчётны ресурсы, проверка гипотез, открытый/верифицируемый артефакт и отсутствие преувеличенных заявлений. Future Fund может рассматривать грант только после отдельного решения владельца.

## 4. Алгоритм для Seven, Sales и QA

`ПОТРЕБНОСТЬ → ДОБРОВОЛЬНАЯ СДЕЛКА ИЛИ БЕСПЛАТНЫЙ ПИЛОТ → СЕБЕСТОИМОСТЬ → ВЫГОДА ВСЕХ СТОРОН → СОЦИАЛЬНЫЕ И ЭКОЛОГИЧЕСКИЕ ИЗДЕРЖКИ → ДОКАЗАТЕЛЬСТВА → QA → ЧЕЛОВЕЧЕСКОЕ ОДОБРЕНИЕ → РЕАЛИЗАЦИЯ → ИЗМЕРЕНИЕ → РЕПЛИКАЦИЯ`

Распределение функций:
- **Seven of Nine:** организует задачную цепочку, требует конкретного результата и отделяет задачу от доказательства её выполнения.
- **Data:** проверяет формулы, данные, отсутствие двойного счёта и сравнимость метрик.
- **Sales / Growth / Unity:** ищут добровольных партнёров и клиентов, не обещают автоматическую прибыль и не отправляют массовые сообщения без разрешения.
- **Tuvok / Sherlock:** проверяют конфликт интересов, альтернативы, неизвестные и ложные причинные выводы.
- **QA Triad:** подтверждает, что приёмка услуги и экономические показатели реально верифицированы.

## 5. Границы текущего внедрения

На момент создания этого документа v4 указан в **реестре 29 GitHub-агентов**. Однако декларация наследования не доказывает, что **каждый** внешний MCP-исполнитель и Cloudflare-профиль проверяет экономические ворота в runtime. Для Cloudflare Galactic Swarm (10 000 виртуальных профилей) и каждого внешнего сервиса нужна отдельная проверка prompt/context injection, прав, исполнения и телеметрии. Число профилей ≠ число реально действующих агентов.

**Этот PR содержит только настройку политик и документацию.** Он не проводит платежи, не меняет текущий WordPress, не выдаёт разрешение на монетизацию метавселенной и не подключает новых исполнителей. Полноценное применение политики в Cloudflare и в продажах — отдельный проверяемый этап.
