# QuantDeus — политика «Никаких мёртвых API» 🖖

**Область:** все 29 агентов, Telegram, форум, GitHub Actions и LLM-маршруты.

## Единственное условие статуса «работает»

Наличие ключа, название модели, HTTP 200 без осмысленного текста и прохождение имитационного теста **не доказывают работоспособность**. В отчёте нельзя писать «LLM работает», пока реальный вызов не вернул корректный непустой текст модели.

- `не настроен` — нет разрешённого бесплатного ключа;
- `не подтверждён` — маршрут есть в настройках, но нет ответа настоящей модели в данном запуске;
- `работает` — получен настоящий ответ модели; фиксируем выбранную модель и время;
- `сбой` — неправильный ответ, сеть, тайм-аут или серверная ошибка;
- `в карантине` — 401/403/404/410 (нет доступа/модели), 402/429 (лимит), а также другие сбои на время охлаждения.

**После сбоя** не запускать лавину повторов, не объявлять фиктивный зелёный статус и не переводить привилегированные действия на обычную текстовую модель. Проверки без внешнего запроса тестируют *логику*, а не работоспособность чужого API.

## Текущий маршрут

`GitHub Actions` исполняет **текстовые** запросы; модель предоставляется `OpenRouter openrouter/free`. Это бесплатный маршрутизатор, но ключ сам по себе не является доказательством его работоспособности. Маршрут допускается в статус `работает` только после живого ответа. Не подставлять платную модель из переменной `QD_LLM_MODEL`.

Не использовать закрытый 30 июля 2026 года `GitHub Models`, в том числе старые адреса API. Не возрождать отменённый GitLab workflow.

В случае недоступности Vercel Sandbox не объявлять доверенные инструменты OpenClaw восстановленными: только текстовый чат может использовать запасной маршрут; GitHub MCP, Playwright и действия в репозитории требуют отдельной реальной проверки.

## Проверки и бюджет

1. При каждом PR запускать `node --test scripts/qa/cloud-llm-client.test.js`: проверка запрета закрытых адресов, live-only статуса и карантина.
2. Ежедневно проверять **одного** агента; ручной полный тест всех 29 запускать только при необходимости и с учётом лимитов OpenRouter.
3. При первом общем сбое провайдера останавливать полный тест и сохранять правдивый результат.
4. Различать подтверждение структуры 29 профилей от 29 реальных LLM-ответов.
5. Не делать никаких автоматических платных переключений и не записывать API-ключи в логи.

**Никакой зелёной галочки без живого успешного запроса.**
