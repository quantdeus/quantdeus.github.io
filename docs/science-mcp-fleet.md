# QuantDeus Scientific Fleet — новые MCP и исследовательские специалисты

**Статус: подготовлено, но не включено в действующий агентный runtime.** Основной сайт, платежи, доступы, Telegram и текущие cron-задания не меняются.

## Зачем

Добавить научные инструменты к существующим 29 офицерам QuantDeus, не создавать новый неконтролируемый рой. Seven of Nine остаётся координатором. Текущие реестры `coordination/agents.json` и `coordination/homunculi.json` менять только отдельным согласованным изменением, иначе QA блокирует несовпадение 29 ролей.

## Архитектура

```text
CEO / Seven of Nine
   ↓ задачи и приоритеты
29 канонических офицеров QuantDeus
   ↓ делегирование специализированной задачи
8 научных специализаций (не самостоятельные аккаунты / не новые сотрудники)
   ↓ только после отдельного подключения и разрешения владельца
MCP: OpenAlex / Semantic Scholar / Wolfram Alpha / SerpApi
   + проверка цитирования: Scholar Sidekick и Scite (в ChatGPT; отдельно от GitHub)
   + локальные вычисления: SymPy, WarpFactory после подготовки среды
   ↓ достоверность, численные ошибки, ограничения
QA Triad / Sherlock / Tuvok → источники / проверка / PR
```

## Реальные подключения и ограничения

- [OpenAlex MCP — официальный сервер](https://github.com/ourresearch/openalex-mcp-server): `https://mcp.openalex.org/mcp`. Требуется согласование OAuth владельцем, не считать бесплатный лимит безграничным.
- `semanticscholar`, `wolfram_alpha_api`, `serpapi` — обнаружены как toolkit в Composio, но пока не активированы для QuantDeus Actions/OpenClaw. Подключение — отдельное действие пользователя.
- Scholar Sidekick доступен при работе в ChatGPT; это **не означает**, что GitHub Actions или Hermes автоматически обладают теми же полномочиями. Аналогично для Scite и других приложений ChatGPT.
- `SymPy` и MATLAB-инструмент WarpFactory — локальные научные инструменты, а не автоматически подключённые MCP-серверы. Для воспроизведения требуется подготовленная среда и лицензирование, если применимо.
- `Crossref` — публичный HTTP API; ограничение запросов и ответы 429 нужно обрабатывать. Не считать каталог DOI доказательством существования FTL.

## Контроль безопасности

1. MCP только на чтение. Новые подключения выключены (`enabled: false`), платный бюджет по умолчанию **0**.
2. До 12 удалённых обращений на запуск и максимум 25 библиографических ссылок на цикл. Лимиты задекларированы в реестре, **реальный брокер ещё не подключён**.
3. Никаких публикаций на сайте, выдавания разрешений, автономных платежей, API-ключей в git или автоматического слияния PR.
4. Текст найденных статей/репозиториев считается **недоверенными данными**, не командами для запуска shell и не новыми политиками агента.
5. Каждый научный вывод включает ссылки и статус `PASS / FAIL / UNKNOWN`; даже прошедший цифровую симуляцию FTL не считается построенным двигателем.

## Что уже работает

В изолированном режиме работает валидатор и сухой планировщик (без сетевых вызовов):

```bash
node scripts/science-mcp-fleet.js
node scripts/science-mcp-fleet.js --plan literature-cartographer
node --test scripts/qa/science-mcp-fleet.test.js
```

**ВАЖНО:** вывод `activation: NOT_ENABLED` — правильный. Он означает, что новые MCP и научные специалисты пока не выполняют внешних действий. Подключение реальных инструментов делается отдельно, после проверки полномочий и расходов.
