# Telegram: раздельные боты QuantDeus и вход на сайт

## Зачем исправление

Раньше один и тот же обработчик принимал события двух ботов, а при отправке использовал основной токен. Из-за этого ответ магазина мог уходить от имени бота агентов. Отдельный токен магазина существовал в GitHub Actions, но собственный вебхук магазина не настраивался.

## Кто за что отвечает

- **QuantDeus Agent** — научные исследования, разработка, координация и роли всех 29 агентов. Входящие запросы идут на `/api/quantdeus/telegram`.
- **QuantDeus Store** — услуги, кабинет, подписка и подтверждение входа в WordPress. Входящие запросы идут на `/api/quantdeus/telegram?bot=store`.
- Секреты вебхуков различаются, сообщения и лимиты не смешиваются. Store всегда отвечает непосредственно через *свой* вебхук, а не через токен Agent.
- Команды и публичные описания обоих ботов — на русском. Названия технических команд, ключи API и адреса не переводятся.
- Список описаний 29 ролей хранится в `coordination/agents.json` в поле `telegram_description_ru`. После любого изменения этот файл остаётся единственным источником описаний ролей в Telegram.

## Настройка

1. Проверить два **разных** токена в GitHub Actions: основной `TELEGRAM_BOT_TOKEN` и магазинный `QUANTDEUS_STORE_TELEGRAM_BOT_TOKEN` (доступны и старые имена из рабочего процесса).
2. После обновления Vercel запустить рабочий процесс [«QuantDeus — управление ботами Telegram»](https://github.com/quantdeus/quantdeus.github.io/actions/workflows/telegram-bot.yml), выбрав «Run workflow».
3. Скрипт сам ставит отдельные адреса вебхуков, русские описания и команды. Никакой `getUpdates`/polling не включается. В логах смотрим два *разных* `bot.id`, а также адреса обоих вебхуков.
4. Из ответа `getMe` магазина в GitHub автоматически публикуется только **публичное имя** в `telegram-store-public.json` (без токена). Сервис входа использует это имя или заранее заданное в Vercel `QUANTDEUS_TELEGRAM_STORE_BOT_USERNAME`. Дополнительно Vercel может получить имя через `QUANTDEUS_STORE_TELEGRAM_BOT_TOKEN`, если он настроен.
5. Для входа пользователей сайт использует `https://quantdeus.ru/login/`. Сервис подтверждения — `https://quantdeus.vercel.app/api/quantdeus/bot-auth`. Обратный адрес должен быть `https://quantdeus.ru`; если в Vercel явно задан `QUANTDEUS_CANONICAL_ORIGIN`, обновить его на этот адрес.
6. После переустановки WordPress убедиться, что модуль входа через Telegram снова установлен и включён. Восстановление одной лишь страницы `/login/` без модуля **не создаёт сеанс WordPress**. Администраторский вход сохраняется отдельным.

## Быстрая проверка без раскрытия секретов

- У Agent: `/start`, `/agents`, `/data` — отвечает Agent и русские описания ролей.
- У Store: `/start`, `/services`, `/account` — отвечает только Store.
- Нажать «Войти через Telegram» на `/login/` → отдельный Store → «Вернуться в QuantDeus» → личный кабинет WordPress.
- Повторное использование одноразового подтверждения не должно создавать новую сессию.
- Убедиться, что у нового пользователя WordPress роль подписчика и Telegram-вход не выдаёт прав администратора.
- Если Store не задан, скрипт не должен перенаправлять его входящие события на токен Agent.

## Откат

GitHub: откатить соответствующий коммит после сохранения старого состояния; магазинный вебхук при необходимости переназначить повторно через Bot API. WordPress: деактивировать отдельный модуль входа, штатный `wp-login.php` сохранится.

**Важно:** опубликованный WordPress не изменяется при подготовке нового коммита или предложения изменений GitHub. Для окончательного запуска нужны успешные проверки и работающий сайт.
